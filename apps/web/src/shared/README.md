# `shared/`: code every website module may use

Small, stable building blocks with no feature logic. Nothing here may import a module or a route (`web-shared-is-shared`).

| Folder | Contents |
| --- | --- |
| `config/` | `site.ts`: public links, the contact address, `SITE_URL` (the deployment's origin, used for OAuth return URLs), `INSTALL_PAGE_URL` (the install guide's full address, which a phone sends to a computer with nothing added, #243), and `TEST_EXTENSION_ID`, the end-to-end tests' extension with a fixed id, taken only on localhost (#302). `store-listings.ts` (#304, [ADR-0034](../../../../docs/adr/0034-distribution-through-the-browsers-stores.md)): Xomoni's Chrome Web Store and Edge Add-ons pages (`CHROME_WEB_STORE_URL`, `EDGE_ADDONS_URL`, empty until the stores list Xomoni), checked by `isStoreListingUrl` (https, the store's own host and listings' path, parsed with `new URL`) into `STORE_LISTINGS`; the extension keeps the same two values, and its tests fail when they differ. `security-headers.ts`: the Content-Security-Policy and other security headers that `next.config.ts` sends with every response ([ADR-0014](../../../../docs/adr/0014-security-headers-and-a-static-csp.md)). `trusted-types.ts`: the site's one Trusted Types policy, which `src/instrumentation-client.ts` installs before hydration. `security-txt.test.ts` checks `public/.well-known/security.txt` (#150), and fails 30 days before its `Expires`. |
| `http/` | Request helpers for route handlers: `same-origin.ts` (`isSameOriginRequest`, the Origin check on state-changing routes) and `csp-report.ts` (reads, trims and logs Content-Security-Policy violation reports for `/api/csp-report`) (#147). |
| `supabase/` | Client factories: `server.ts` (Server Components, Actions, Route Handlers; `server-only`), `browser.ts` (Client Components), `browser-session.ts` (`watchSessionEmail`: who the session cookie names, with their display name so the header's avatar shows the dashboard's initials (#239), for the header; not a security check), `proxy.ts` (the Next.js proxy: refreshed session cookies carried on its redirects and rewrites), and `env.ts` (validated public settings). |
| `ui/` | `fluent-provider.tsx` (Fluent UI with server-rendered styles and no dark-mode flash, ADR-0019; it holds Fluent's focus manager while the site is open, so the page behind a dialog never stays hidden from assistive technology, #315), `links.tsx` (`ButtonLink` and `TextLink`: links that look like Fluent buttons and links but keep `next/link` for the site's pages; a `ButtonLink` may run a click handler as it is followed, #299), `site-chrome.tsx` (logo, header, footer; on public pages the header links the home page's sections, GitHub and *Install*, folded below 768 px into one keyboard-operable *Menu*, which closes once the screen is 768 px or wider, a phone turned on its side, and the footer links Install, What's new, Risks, Privacy, Terms, Security, Support and GitHub, #242; the header and footer stay off a printed page, `data-print="hide"`, #257. Its user scenarios, the phone's menu and the footer, are in [`docs/scenarios/242-phone-menu.md`](../../../../docs/scenarios/242-phone-menu.md), tagged `@task-242`), `use-session.ts` (`useSession`: who is signed in on this browser, from its session cookie, for what a page shows; #244), `header-account.tsx` (the header's account corner on every page: *Sign in* for visitors, *Dashboard* and an account menu with *Sign out* for signed-in people, #180) and `legal-page.tsx` (layout for the risks and policy pages, styling the plain HTML text they write). |

## Rules

- `web-shared-is-shared`: no imports from `modules/` or `app/`.
- `web-supabase-behind-adapters`: `shared/supabase` is one of the two places allowed to import `@supabase/*` and `@xomoni/db`; module code reaches Supabase only through its `infrastructure/` adapters.
- `web-server-code-is-server-only`: `supabase/server.ts` imports `server-only`.
