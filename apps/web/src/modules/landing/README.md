# `modules/landing`: the landing and install pages

The page at `/` that tells a first-time visitor what Xomoni is: a **digital footprint manager** (#313). It names the five things Xomoni does (discover, understand, clean up, protect, shape) with what each is on X today, the places it covers (X today, the person's email next, then the other places they are present; no dates), how it works on X, its principles and safety rules, what stays private, common questions and how to start. And `/install`, the guide to installing the extension from its latest GitHub release (#44), ending with the install questions (#306). Once a store lists Xomoni (#304, [ADR-0034](../../../../../docs/adr/0034-distribution-through-the-browsers-stores.md)), `/install` is one button for the visitor's browser, and the zip's guide moves under *Advanced: install from a zip*; until then it is unchanged. Both are built on Fluent UI with Xomoni's theme ([ADR-0019](../../../../../docs/adr/0019-fluent-ui-everywhere.md)); their styles are rendered on the server by `shared/ui/fluent-provider.tsx`, so the pages arrive styled.

The module has no data and no actions: a pure `domain/` with what Xomoni is and the install guide's rules, and a `ui/` layer. The store listings it offers come from `shared/config/store-listings.ts`.

## Rules

- **The copy stays true to the product.** Claims about data and safety match the [privacy policy](../../app/privacy/page.tsx), [ADR-0003](../../../../../docs/adr/0003-no-credentials-no-evasion.md), [ADR-0004](../../../../../docs/adr/0004-x-data-stays-local.md) and [ADR-0006](../../../../../docs/adr/0006-website-is-view-only.md); change them together.
- **Only what exists today, and no dates.** Xomoni works on X only. A place that is planned (`next`, `later`) says so and names no feature and no date; its type can't carry one, and a test checks the words. X's lines under each pillar name features that ship.
- **One story about risk.** The page says Xomoni stays within X's *limits* and protections, never that it follows X's *rules*: X's rules forbid automating its website, as the hero's risk line, the FAQ and `/risks` (`@xomoni/consent`) say.
- **No platform logos.** Platforms are named in words only, with the line that Xomoni isn't affiliated with, endorsed by or sponsored by X Corp. The rule is [ADR-0035](../../../../../docs/adr/0035-xomoni-has-its-own-mark.md).
- **Illustrations are drawn, never recorded** (#299): schematic SVG in the theme's colors, labelled *Illustration*, with the browser's own labels in `VISUAL_WORDS`; a screen recording would go stale with every browser update and can't be made of the native file dialog. The step's words stay the instruction; a drawing's caption says the same and never more. No browser's or platform's logo.
- **Screenshots come from the dashboard preview** with demo data, never from a real X account: `public/screens/overview.png` (light, also the Open Graph image) and `overview-dark.png`, both 1440 × 1000. `npm run store:images -w @xomoni/extension` takes them with the stores' screenshots, so they show the current sidebar and logo (#322). For a phone (up to 639 px wide), `overview-narrow.png` and `overview-narrow-dark.png`, 920 × 1160: Home in a 700 × 900 window at twice the pixels, its main column's top 460 × 580 (from x = 240, past the sidebar), so it reads at a phone's width (#243).
- **On a phone, nothing to install** (#243). Xomoni installs only on a computer, so a phone gets *Send to my computer* wherever a computer gets an install button. The link goes as it is (`INSTALL_PAGE_URL`, no tracking), through the phone's own share sheet, clipboard or mail app; nothing reaches a server. The desktop page doesn't change.
