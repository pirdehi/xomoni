# `modules/dashboard`: devices and live job status

Shows the signed-in person which browsers have the extension connected and how their jobs are doing, updating live: jobs that need the person come first (_Needs you_), then each X account's risk level (#41). It is read-only toward X: the only changes it can make are a one-time code that connects a browser, typed or handed to the extension that asked on `/connect` ([ADR-0024](../../../../../docs/adr/0024-connect-a-browser-with-one-click.md)), ([ADR-0018](../../../../../docs/adr/0018-pair-the-extension-with-a-one-time-code.md)) and disconnecting a device ([ADR-0006](../../../../../docs/adr/0006-website-is-view-only.md)).

## Data flow

1. `app/dashboard/page.tsx` calls `requireViewer()` (auth module) and `loadDashboardSnapshot()`.
2. The page renders `<Dashboard initial={snapshot}>`.
3. `useLiveDashboard` subscribes to Realtime changes filtered by the user's id, on a private channel `dashboard:<user id>` that a policy on `realtime.messages` opens to its owner only (#81). Realtime and PostgREST both enforce Row Level Security.
4. A browser connects with a code from `PairingPanel`: the extension trades it for a device token (`pair_device`) and reports through `device_report`; the new device and its jobs arrive over the same live feed.
5. _Needs you_ and _X accounts_ are derived from the jobs on every change, so they update live too. An account appears only once a job reported its level; the level is per browser, because each browser's extension keeps its own risk ladder.
