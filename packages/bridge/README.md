# `packages/bridge`: what xomoni.com and the extension say to each other

The messages xomoni.com and the Xomoni extension exchange inside one browser, through Chrome's `externally_connectable` ([ADR-0024](../../docs/adr/0024-connect-a-browser-with-one-click.md), [ADR-0025](../../docs/adr/0025-one-sign-in-for-the-website-and-the-extension.md)). Both apps import it as `@xomoni/bridge`, so the two sides can't drift. Every parser is strict: exact keys and shapes, anything else is refused.

| Export | Used by |
| --- | --- |
| `WEBSITE_ORIGIN` | The extension's sender check: only xomoni.com's top frame is heard. |
| `HELLO`, `SIGN_IN`, `SIGN_OUT`, `PAIR`, `JOB`, `OPEN` and their message types | The website builds them; the extension's service worker reads them with `parseWebsiteMessage`. `JOB` pauses, cancels or asks to resume a job (`JobAction`, never a start); `OPEN` opens one of Xomoni's pages (`XomoniPage`, the Vault page among them since #425). Both name the device the page's account knows (ADR-0027). |
| `READ` and `ReadMessage` (`ReadWhat`, `LibraryKind`, `LIBRARY_KINDS`, `READ_PAGE`, `MAX_READ_QUERY`) | The website asks Xomoni for one of its places (ADR-0028): a page of the Library (a kind, a search of at most 100 characters, an offset), Watch or account health, naming the device the page's account knows. `what: 'vault'` asks for the vault's summary (#426). |
| `RepliesFilter`, `parseRepliesFilter`, `RepliesPage`, `ReplyItem`, `RepliedTo`, `MAX_REPLIED_TO` | A `replies` read (#256): the person's replies still on X, filtered by date, at most a number of likes, the handle they answer and words, with an offset. The answer is a page of replies, each with the handle it answers and whether it is in the person's own thread, and the `MAX_REPLIED_TO` (20) people replied to most. |
| `IncomingPage`, `IncomingReply`, `INCOMING_DAYS` | An `incoming` read ([ADR-0030](../../docs/adr/0030-replies-to-you-kept-on-the-computer.md)): the replies others wrote to the person that Xomoni kept, by author (a handle or empty) and words, with an offset. The answer counts the kept replies, says since when, gives the replies per local day (at most `INCOMING_DAYS` + 1 days), the 20 people who reply most, and a page of replies, each with its author and the person's post it answers. |
| `ReadAnswer`, `parseReadAnswer`, `LibraryPage`, `LibraryItem`, `AccountHealth`, `WatchTabView`, `MAX_READ_TEXT` | The website reads the answer for the place it asked about: at most `READ_PAGE` (100) items, texts of at most `MAX_READ_TEXT` (1,000) characters, or a refusal. Anything else is no answer. |
| `SETTINGS`, `SettingsMessage`, `SettingsChange`, `parseSettingsMessage`, `ActiveHours`, `PaceAction`, `PACE_ACTIONS`, `MAX_WATCH_SEARCHES` | The website asks Xomoni to change a fixed few settings (ADR-0029): pacing back to Careful only, active hours, notifications, keep going while away, failures in a row (1–3), and the active account's Watch searches (at most five, 100 characters each). Anything else, such as a faster pace, is refused. |
| `PLAN`, `PlanMessage`, `CleanupPlan`, `parsePlan`, `parsePlanMessage`, `MAX_PLAN_KEYWORDS`, `MAX_PLAN_KEYWORD`, `MAX_PLAN_IDS` | The website hands Xomoni a cleanup plan (#235): what, before when, optionally from when, likes and words to keep (at most 20, 50 characters each), and threads. Dates must be after 2006 and not later than tomorrow, and the start before the end. A plan may also pick posts by id (`onlyIds`, 1 to `MAX_PLAN_IDS` (500) distinct ids, #256); a plan by date has no such key. Xomoni answers as for an action (`opened`). |
| `CleanupEstimate` | A `cleanup` read's answer: how many items the plan matches in Xomoni's copy, whether the archive was imported, and the most a day at the current pace. Counts only. |
| `XomoniSettings`, `SettingsAnswer`, `parseSettingsAnswer` | The settings as Xomoni stored them: read with `xomoni-read` (`what: 'settings'`) and answered after a change. |
| `VaultSummary`, `VaultSourceSummary`, `VaultFreshness`, `VAULT_FRESHNESS`, `VAULT_SUMMARY_SOURCES`, `parseVaultSummary` | The vault's summary (#426, ADR-0028 as amended): each source's date, freshness and rows, the day X made the newest archive, the imports and the reading groups on. Counts and dates only; an answer with any other key, a count that isn't whole, or a source or freshness the bridge doesn't know is refused. |
| `ActionAnswer`, `parseActionAnswer` | The website reads what the extension did with an action (`stopping`, `cancelled`, `asked`, `opened`) or why it refused. |
| `ExtensionState`, `parseExtensionState` | The extension's answer to a hello: its version, its xomoni.com connection (device id and masked account, never the token), since when it is signed out, and when the person last left xomoni.com there. |
| `parseSignInAnswer`, `parseSignOutAnswer` | The website reads the extension's answers. |
| `isExtensionId`, `EXTENSION_ID`, `PAIRING_CODE`, `NONCE`, `DEVICE_ID`, `JOB_ID` | Shapes both sides check. |
| `STORE_EXTENSION_IDS`, `Store`, `storeExtensionIds` (`src/extension-ids.ts`) | Xomoni's fixed id in the Chrome Web Store and in Edge Add-ons, null until the stores exist: the one place they are written (#302). xomoni.com asks them for Xomoni without `#ext=`, Chrome's first; writing one is all it takes. |
| `readManifestKey`, `ManifestKey`, `manifestKeyProblems` | The extension's manifest test: a `key` must be base64 of an RSA public key (SubjectPublicKeyInfo, 2048 bits or more), and the id Chrome derives from it (SHA-256, first 128 bits, 0–f as a–p) must be `STORE_EXTENSION_IDS.chrome`; no key, no Chrome id. Web Crypto, so the same in Node and a browser. |

## Rules

- `packages-do-not-import-apps`: this package depends on nothing in `apps/`.
- No message carries X content to a server ([ADR-0004](../../docs/adr/0004-x-data-stays-local.md)). Only a read answer carries the person's own X content, to xomoni.com's page in the same browser, which keeps it in memory only ([ADR-0028](../../docs/adr/0028-xomoni-data-on-the-website-in-the-same-browser.md)). None can start or approve work on X: a resume only asks the person in Xomoni ([ADR-0027](../../docs/adr/0027-extension-actions-from-the-website.md)). A new message type needs the ADR updated.

## Tests

`tests/bridge.test.ts`: every message shape, the refusals (other types, extra fields, malformed codes, devices and nonces, reads past their limits), and the answers. `tests/extension-ids.test.ts`: the stores' ids and their order, and manifest keys (a test key whose id Chrome confirmed, keys that aren't base64, EC or too short, and every way the key and the Chrome id can disagree). 100% coverage.
