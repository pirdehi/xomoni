# `modules/admin`: the super-admin console

The console at `/product` (#516) where the site's super-admins run the product: an overview of accounts, browsers and jobs; every account, searchable, sortable and paged, with its browsers, recent jobs, plan, choices and sessions; actions on an account (sign out everywhere, suspend and restore, delete), each recorded in an audit log; the maintainer's private plan as their own tool publishes it; and the product document of [ADR-0048](../../../../../docs/adr/0048-a-private-product-document-for-super-admins.md) with its versions. Who is a super-admin is in `public.app_admins`, filled by the maintainer with SQL.

Everything goes through database functions that the signed-in person calls (`admin_overview`, `admin_users`, `admin_user`, `admin_sign_out_user`, `admin_set_banned`, `admin_delete_user`, `admin_audit_log`) and the table `public.product_plan`. Each function checks itself that the caller is a super-admin, at aal2 when their account has an authenticator app, refuses an action on the caller's own account or another super-admin's, and writes the audit log in the same transaction. The website holds no service-role key.

Nobody else learns the console exists: the proxy answers anyone signed in who isn't a super-admin with the site's own 404 page and a real 404 status before any page renders (a page's own `notFound()` streams inside a 200 under Cache Components); the layout draws the console's frame only for a super-admin; each page and each Server Action checks again (`requireSuperadmin`); and the database checks once more.

## Routes

- `app/product/(console)/layout.tsx`: the frame around every console page.
- `app/product/(console)/page.tsx` `/product` (overview), `users/page.tsx` `/product/users`, `users/[id]/page.tsx` `/product/users/<id>` (`instant = false`: an account's id is known only at request time, and the root layout reads the address outside a Suspense boundary, so the page may block instead of prerendering a shell), `roadmap/page.tsx` `/product/roadmap`, `audit/page.tsx` `/product/audit`, `documents/page.tsx` `/product/documents` (product-docs' versions page inside the console).
- `app/product/login/page.tsx` `/product/login`: the console's own sign-in, outside the frame; anyone may open it.
- `app/product/document/route.ts` `/product/document`: the product document itself (product-docs), sandboxed, opened from the sidebar in a new tab.

## Used by

- The routes above.
- `modules/auth`: its proxy sends a signed-out visitor on a console page to `/product/login` (`signInPathFor`) and answers a signed-in stranger with the 404 (`isConsolePage`, `is_superadmin()`); its `session.ts` gives the console `requireViewer`, `currentViewer`, `sameSitePath` and `secondFactorPath`; its `ui/` gives the sign-in form its fields, security check and navigation.
- `modules/dashboard/ui/charts.tsx` draws the sign-ups chart.
