# `modules/algorithm`: the digest of X's open ranking code

xomoni.com/algorithm (#430, [ADR-0046](../../../../../docs/adr/0046-a-public-digest-of-xs-open-ranking-code.md)): each month X's open-source ranking code changed, a digest of what changed, made from X's public repository [`xai-org/x-algorithm`](https://github.com/xai-org/x-algorithm) only. A workflow drafts it ([`tooling/algorithm-digest.mjs`](../../../../../tooling/algorithm-digest.mjs), on the 20th of each month), and a maintainer writes the summary and publishes it ([guide](../../../../../docs/guides/ALGORITHM-DIGEST.md)). The pages show published digests only, as static pages the same for every visitor: no cookie, no request to Supabase or anyone else, nothing about any person.

The module has no database table and no actions: the digests are files in the repository, checked when the site is built.

## Layers

| Layer | Files | Responsibility |
| --- | --- | --- |
| `data/` | `index.ts`, `<yyyy-mm>.json`, `e2e.ts` | The digests as files. `<yyyy-mm>.json`, one per month, and `index.ts`, which imports them all as `DIGEST_FILES` (`unknown` until checked), are written by the workflow's tool and reviewed in its pull request: don't edit `index.ts` by hand. `e2e.ts`: the end-to-end tests' made-up digests of the year 2000 (`E2E_DIGEST_FILES`: January published and complete, February published with markup for a commit message and no parameter, March a draft), shown only by the tests' build. |
| `domain/` | `digest.ts`, `parse.ts` | `parse.ts`: the strict check, which only the server runs, with zod in its jitless mode (the site's Content-Security-Policy refuses the `new Function` zod would probe for, ADR-0014); the pages' components only `import type` from it, so no zod reaches the browser. `parseDigest` reads a file from `unknown` with a strict zod schema: version 1 and no other field, the repository, a month, two different full commit ids, a day, `draft` or `published`, a summary of at most 2,000 characters that a published digest must have, counts, known areas (`AREAS`) each once with up to 10 file names, up to 50 parameter names and 20 commit messages, every line of outside text clean (no control, zero-width or direction character, no space at either end, at most 200 characters), as the tool cleans it. `digest.ts`, with no schema: `publishedDigests` (published only, newest first), `AREA_WORDS` (each area's name and one sentence on what its code does), `monthLabel`, `dayLabel`, `shortCommit`, `compareUrl` (the range on GitHub), `paragraphs` (the summary split at blank lines), `isMonth` and `digestHref`. |
| `server/` | `digests.ts` | `server-only`. `readDigests` checks every file and throws for one that isn't a digest, naming it and what is wrong, or for two of one month, so the build fails rather than show or skip it. `digestList` (what /algorithm lists), `digestOr404` (a published month, else Next.js's 404: a draft, a month with no digest, an address that isn't a month), and `digestMonths`, the pages built ahead: every published month, or one address that answers 404 (`NO_DIGEST`) while there is none, as Cache Components need one. `showsSampleDigests`: the tests' digests join only when `XOMONI_E2E_DIGESTS=1` and the site is on localhost, so a stray setting in Vercel can't publish them. |
| `ui/` | `digest-shell.tsx`, `digest-list.tsx`, `digest-page.tsx` | `DigestShell`: the site's header, an eyebrow, the title and a line under it, the text, and the footer, on Fluent's tokens; file and parameter names wrap anywhere, so a phone never scrolls sideways. `DigestList`: the published digests newest first, each linking its month with how far it goes, its commits and its areas (`digestLine`), or *No digest is out yet*; how a digest is made; and what it can't tell (`LIMITS_TEXT`: X hides the real weights). `DigestPage`: the month in the title, the range by short commit ids with its commits and files (`rangeLine`), the summary's paragraphs, what it can't tell, a table of the areas (row headers with what each does, the count, some file names, and a caption when GitHub cut the list at 300), the parameter names with how many more, X's commit messages, *See every change on GitHub* (the exact range, in a new tab with `noopener noreferrer`) and *All digests*. Everything from X's repository is React text, never HTML. |

## Rules

- **Public code only** (ADR-0046). Nothing here reads, stores or shows data about a person, sets a cookie or asks Supabase anything. The pages can be shown to anyone, signed in or not.
- **Published only.** A draft never shows: its address answers 404, and the list and the sitemap leave it out.
- **Made ahead, never streamed.** Both routes set `ensureStatic = 'navigation'`: every page is built in full before it is served, so an address with no published digest answers with a real 404 status, not a page that says so under a 200 (with Cache Components, a page that streams has sent its status before `notFound()` runs).
- **Outside text is text.** Commit messages, file names and parameter names come from a repository Xomoni doesn't control. `parseDigest` refuses what the tool would have cleaned, and the pages render them as React text, under the site's Content-Security-Policy, unchanged ([ADR-0014](../../../../../docs/adr/0014-security-headers-and-a-static-csp.md)).
- **Say what it can't tell.** Every page says the real weights are hidden. The maintainer's summary follows the guide: structure only, every claim pointing to a file of the range, no promise and no advice.

## Tests

Next to each file: `domain/` (every field of the shape, bad months, commits and days, unknown and repeated areas, unsafe characters one by one, markup kept as text, the limits, published only and newest first, the words), `server/` (the samples only on a local tests' build, a broken file or two files of one month failing the build, 404 for a draft, an unknown month and an address that isn't one, the pages built ahead), `data/` (every file of the folder in the index, in order, each a digest in the file of its month) and `ui/` in happy-dom (the list, its lines and its empty state; the page's headings in order, the summary's paragraphs, the table, the capped list, no parameter, no message, markup shown as text and absent from the server's HTML, the GitHub link's range, tab and `rel`). End to end: [`e2e/algorithm-digest.spec.ts`](../../../e2e/algorithm-digest.spec.ts), the user scenarios of [`docs/scenarios/430-algorithm-digest.md`](../../../../../docs/scenarios/430-algorithm-digest.md), each test named by its id and tagged `@task-430`, on the tests' made-up digests: the list and a month, the GitHub link, the footer, the sitemap, 404 for a bad month, an address that isn't one, a month with none and the draft, markup that never runs, no cookie and no request to any other origin, GitHub's tab unable to reach back, the page without its scripts, with Supabase down and with GitHub unreachable, a month with no parameter, *All digests* and Back, the keyboard alone, axe in both themes, headings and the table for a screen reader, a phone in dark mode, and a reload. `e2e/a11y.spec.ts` checks /algorithm and a month with the other pages.
