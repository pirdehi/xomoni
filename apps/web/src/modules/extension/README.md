# `modules/extension`: the Xomoni extension in this browser

Finds the Xomoni extension installed in the same browser (by the id a page of Xomoni named, `#ext=`, or by a store's fixed id, #302), keeps xomoni.com and the extension signed in and out together: one sign-in (#232, [ADR-0025](../../../../../docs/adr/0025-one-sign-in-for-the-website-and-the-extension.md)), and hands it the website's actions, or says in one dialog why it can't (#251, [ADR-0027](../../../../../docs/adr/0027-extension-actions-from-the-website.md)). It talks to the extension through Chrome's `externally_connectable`, with the messages in [`@xomoni/bridge`](../../../../../packages/bridge/README.md). Nothing here sends X content to a server ([ADR-0004](../../../../../docs/adr/0004-x-data-stays-local.md)): what a page reads from Xomoni (the Library, Watch, account health, the settings, how much a cleanup plan matches, the person's replies and the replies others wrote to the person, #256, ADR-0030) stays in that page's memory, never in storage, logs or reports ([ADR-0028](../../../../../docs/adr/0028-xomoni-data-on-the-website-in-the-same-browser.md), #233). Nothing can start or approve work on X: an action pauses or cancels a job, opens a page of Xomoni, or asks the person to resume in Xomoni ([ADR-0027](../../../../../docs/adr/0027-extension-actions-from-the-website.md)).

## Used by

- `app/layout.tsx`: `ExtensionSessionSync` on every page.
- `modules/landing/ui`: the install page's checklist (`GettingStarted`, `useExtensionLink`), and _Send to my computer_ on a phone (`SendToComputer`, #243) on the home page and /install.
- `modules/dashboard/ui`: `/connect` keeps the extension's id (`rememberExtensionId`); the dashboard marks _This browser_ and hides the finished _Finish connecting_ notice (`useExtensionLink`); job cards and places that need Xomoni use `useXomoni`, `XomoniJobActions` and `OpenInXomoni` (#251).

## Rules

- The usual layer rules (`npm run arch`). `domain/` and `application/` may import `@xomoni/bridge`, a pure contract (ADR-0025).
- Times compared by `decideSync` all come from this computer's clock: the extension's and the site's own records, never the server's.

## Tests

Next to each file. `domain/` and `application/` with fakes for every port; the adapters with fake runtimes, storage, Supabase clients and lock managers; `ui/` in happy-dom (fragment, syncs, sign-out forms). `client/fixed-ids.test.ts` and `ui/fixed-id.test.tsx` add the stores' ids as they will be written and stub `chrome.runtime` (#302): a Chrome or Edge copy found without `#ext=`, both answering, a named zip install first, a gone one falling back, a copy that never answers, `lastError`, no `chrome.runtime`, the sign-out, and the checklist ticking. End to end: `e2e/fixed-id.spec.ts` loads a real unpacked test extension with a fixed `key` in Chromium (#302): Chrome gives it the id its key makes, and the install checklist, /welcome, a stale `#ext=` and the one sign-in and sign-out work with no `#ext=` at all. `e2e/one-sign-in.spec.ts` and `e2e/xomoni-actions.spec.ts` play the extension in a real browser against a local Supabase (the actions, the dialog without Xomoni, on a phone, the places read from Xomoni, and Settings changed in it); `e2e/install.spec.ts` plays it on /install and /welcome (the live checklist ticking when Xomoni opens /welcome in another tab, and the pin hint, #299). `e2e/cleanup-plan.spec.ts` and `e2e/extension/cleanup-plan.spec.ts` hold the cleanup plan's user scenarios ([`docs/scenarios/235-website-cleanup-plan.md`](../../../../../docs/scenarios/235-website-cleanup-plan.md), tagged `@task-235`). `e2e/website-actions.spec.ts` holds the actions' user scenarios ([`docs/scenarios/251-website-actions.md`](../../../../../docs/scenarios/251-website-actions.md), each test named by its id and tagged `@task-251`): each action and Xomoni's every answer, a job of another browser, the dialog without Xomoni, on a phone, the keyboard and axe; `e2e/extension/website-actions.spec.ts` proves Xomoni's side in the built extension.
